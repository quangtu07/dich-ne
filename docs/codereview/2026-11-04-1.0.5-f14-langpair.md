### CR-11 — E22 chặn nhầm output khi đích không phải tiếng Việt (blocker)

`LookupPipeline.mlkitResult` (`:299-321`):

```kotlin
val hasVietnamese = looksVietnamese(translated)
val payload = CachedPayload(translation = translated.takeIf { hasVietnamese }, provider = MLKIT_PROVIDER)
...
errorCode = LookupErrorCodes.E22.takeIf { !hasVietnamese }
```

`looksVietnamese` chỉ kiểm ký tự Việt. Với đích EN/ZH/KO/JA, bản dịch (tiếng Anh/Trung/Hàn/Nhật) **không bao giờ** có ký tự Việt ⇒ `translation = null` + `errorCode=E22`, và payload null còn bị **ghi vào cache** theo key cặp mới ⇒ lượt sau cache hit vẫn rỗng.

Đối chiếu: 3 client online đã gate đúng — `MyMemoryTranslator.kt:75`, `GeminiClient.kt:127/144`, `OpenAiCompatibleTranslator.kt:110/119` đều dùng `TargetLanguages.isVietnamese(targetLang) && !looksVietnamese(...)`. Chỉ pipeline (ML Kit) thiếu gate này.

**Hệ quả:** AC39/AC40 đường offline (máy bay + đã tải gói) dịch VI→EN hoặc ZH→VI (khi online fail) sẽ ra sheet rỗng + "Chưa có nghĩa tiếng Việt". Nguy hiểm hơn: kết quả rỗng bị cache.

**Cách sửa:** trong `mlkitResult`:

```kotlin
val valid = if (TargetLanguages.isVietnamese(targetLang)) looksVietnamese(translated)
            else translated.isNotBlank()
val payload = CachedPayload(translation = translated.takeIf { valid }, provider = MLKIT_PROVIDER)
errorCode = LookupErrorCodes.E22.takeIf { TargetLanguages.isVietnamese(targetLang) && !valid }
```

**Kiểm chứng:** thêm test pipeline cho ML Kit với `targetLang=en` (nguồn VI) → `state=OK`, `translation` có chữ, `errorCode=null`; `zh→vi` → vẫn E22 nếu ML Kit trả nguyên tiếng Trung; `en→vi` giữ test cũ `mlkitEnglishOutput_markedE22_noFakeMeaning`.

### CR-12 — Câu tiếng Trung luôn bị coi là "không chắc" (blocker AC39)

`LanguageDetector.detect` (`:84-88`): `if (top.key == ZH && kana == 0) return Detection(ZH, uncertain = true)` — **mọi** text Hán thuần đều `uncertain=true`, không phụ thuộc độ dài. FE `ResultSheet.kt:272` đổi chip thành `?` khi cờ này ⇒ câu tiếng Trung ra `? → VI`, trong khi:

- **AC39** (spec 1.23): "chip hiện đúng cặp (vd `Câu · ZH → VI`), không hiện `EN → VI`".
- **QA14-12** (`docs/qa/1.0.5-final-pass-sheet.md`): tra câu ZH → chip `Câu · ZH → VI`.
- **Plan R42** lại ghi "Han thuần → ZH, `uncertain`" — tức tài liệu đang mâu thuẫn nhau, không chỉ code sai.

**Đề xuất (cần Spec/Designer chốt):** giữ `uncertain` cho Hán **ngắn** (`letters < MIN_CONFIDENT_LETTERS` hoặc dưới ~10 chữ) và text **trộn script**; Hán thuần **đủ dài** → `ZH` chắc chắn (thực tế câu tiếng Nhật luôn có kana). Khi đó chip ZH hiện đúng, QA14-12/AC39 pass; Kanji-only vẫn rơi vào nhánh ngắn/không chắc nếu có.

**Kiểm chứng:** sửa `LanguageDetectorTest.chineseSentence_isZh` (đang assert `uncertain=true`) thành câu ZH dài → `uncertain=false`, thêm case câu Hán 2–3 chữ → `uncertain=true`; test chip `ZH → VI`.
