### CR-01 — MyMemory: 5xx bị dán nhãn QUOTA (blocker)

`MyMemoryTranslator.kt:97-100`:

```kotlin
if (status == 429 || status in 500..599) {
    return TranslationOutcome.Failure(HttpErrors.E4, FailureReason.QUOTA, httpStatus = status)
}
```

**Tại sao sai:** spec 1.16 tách 2 trạng thái. 5xx = nguồn hỏng tạm thời (E28), chỉ 429/`quotaFinished` mới là hết lượt (E19). Gộp làm một thì lỗi mạng/nguồn chết bị báo "Hết lượt dịch miễn phí hôm nay", user tưởng phải chờ mai.

**Cách sửa:**
- `429` (hoặc body `"status code": 429` — research §9) hoặc `quotaFinished == true` → `FailureReason.QUOTA`.
- `status in 500..599` → `FailureReason.UNAVAILABLE` (thêm vào enum `HttpErrors.kt`), giữ `httpStatus`.
- Timeout/IO giữ nguyên `TIMEOUT` / `IO`.

**Kiểm chứng:** `MyMemoryTranslatorTest.http500_mapsToQuota` (dòng 95) đang **khẳng định hành vi sai** — đổi thành `http500_mapsToUnavailable`; thêm case body 200 + `"translatedText":"QUERY LENGTH LIMIT EXCEEDED…"` → `NOT_VIETNAMESE`/`UNAVAILABLE`, không phải `QUOTA`.

### CR-02 — Mozhi: cùng lỗi, và là gốc BUG-16 mà runtime đã thấy (blocker)

`KeylessFallbackTranslator.kt:121-127` (`MozhiTranslator.lookupChunk`):

```kotlin
if (status == 429 || status in 500..599) {
    return@withContext TranslationOutcome.Failure(HttpErrors.E4, FailureReason.QUOTA, httpStatus = status)
}
```

**Tại sao quan trọng:** research §9 ghi Mozhi **không có khái niệm quota**; khi upstream 429 hoặc instance chết/quá tải, Mozhi trả **HTTP 500**. Code lại map 500 → `QUOTA`, nên chain nhận `QUOTA` từ nguồn thứ 2 rồi pipeline mới in E19/`ERROR_QUOTA`. Đây đúng là chuỗi mà QA gặp: 2 host Mozhi chết + MyMemory hết lượt → app kết luận "hết lượt" thay vì "nguồn tạm không dùng được". Researcher chỉ điểm `MyMemoryTranslator.kt:97`; **phải sửa thêm file này**, nếu không BUG-16 không đóng.

**Cách sửa:**
- `429` từ chính Mozhi (hiếm) → `QUOTA`.
- `5xx` → `UNAVAILABLE`.
- `IOException`/`TIMEOUT` → `IO`/`TIMEOUT` (đã đúng).
- `TRANSIENT_FAILURES` (`:195-200`) thêm `UNAVAILABLE` để instance hỏng vẫn được cache 5 phút; bỏ `QUOTA` khỏi tập này chỉ khi không còn đường nào sinh `QUOTA` do 5xx.

**Kiểm chứng:** `MozhiTranslatorTest.bothInstancesFail_mapsToQuota` (dòng 91) đang enqueue `429` — giữ, đổi tên cho rõ. Thêm `bothInstancesFail500_mapsToUnavailable` (primary + secondary cùng 500). Chạy: `./gradlew :app:testDebugUnitTest --tests '*MozhiTranslatorTest*'`.

### CR-03 — Pipeline: E3a che mất mọi reason (high)

`LookupPipeline.kt:139-149`:

```kotlin
return when {
    canOffline -> errorResult(..., E3A, ...)          // ← luôn thắng
    failure.reason in NETWORK_ISH -> E3B
    failure.reason == QUOTA -> E19
    ...
}
```

**Tại sao sai:** với text trong ngưỡng offline mà **chưa tải gói**, mọi lý do (QUOTA, 5xx, IO) đều ra E3a "Chưa tải gói offline… Bật mạng". Đó chính là kết quả runtime của AC25/E19: QA dựng "cả chain fail" nhưng nhận E3a. Với spec 1.16, khi máy **đang có mạng** mà nguồn hỏng thì phải ra E28; "Bật mạng" chỉ dành cho mất mạng thật. E19 cũng gần như không chạm được với text ngắn.

**Cách sửa (giữ nguyên thứ tự ưu tiên tài liệu):**

1. `failure.reason in {IO}` → `canOffline ? E3A : E3B` (mất mạng thật).
2. `failure.reason == QUOTA` → E19.
3. `failure.reason == UNAVAILABLE` (hoặc `HTTP` 5xx) → **E28** "Nguồn dịch miễn phí tạm không dùng được, thử lại sau".
4. `HTTP` 401/403 → E20; junk (`EMPTY`/`NOT_VIETNAMESE`/`PARSE`) → E5; còn lại → E4.

Giữ nguyên nhánh "model sẵn sàng → ML Kit" ở `:136` (đúng AC25).

**Kiểm chứng:** thêm test ma trận `(reason, canOffline, modelReady) → errorCode`; tối thiểu 3 case mới: text ngắn + không gói + `QUOTA` → E19; + `UNAVAILABLE` → E28; + `IO` → E3a. Hiện `LookupPipelineTest` chỉ có `quotaLongText_mapsToE19` (:288) và `quotaShortTextWithModel_fallsBackToMlkit` (:305), **thiếu** case text ngắn + không gói.

### CR-04 — `responseStatus` chết (medium)

`MyMemoryTranslator.kt:178` khai báo `@SerialName("responseStatus") val responseStatus: Int?` nhưng không đọc ở đâu. Research §9: MyMemory trả **HTTP 200** + `responseStatus: 403` + câu lỗi trong `translatedText` khi query/ngôn ngữ sai. Hiện code chặn nhờ `looksVietnamese()` (`:70`) nên không lọt ra UI — nhưng đó là chặn tình cờ, không phải phân loại.

**Cách sửa:** hoặc dùng (`responseStatus != 200` → log `mymemory body-status=<n>`, trả `UNAVAILABLE`), hoặc xoá field. Đừng để field chết — `ignoreUnknownKeys = true` khiến nó vô hình với test.

**Kiểm chứng:** test body 200 + `"responseStatus":403` → reason là `UNAVAILABLE` (nếu dùng) hoặc không còn field (nếu xoá).

### CR-05 — Mozhi parse JSON bằng regex (medium)

`KeylessFallbackTranslator.kt:158-169` tự regex + unescape tay. Project đã có `kotlinx.serialization` và `MyMemoryTranslator` decode đúng chuẩn. Rủi ro: không xử lý `\uXXXX`, có thể khớp `"translated-text"` nằm trong thông điệp lỗi lồng nhau, vỡ khi instance đổi format.

**Cách sửa:** `data class MozhiResponse(@SerialName("translated-text") val translatedText: String?)` + `Json { ignoreUnknownKeys = true }`, giữ `parseTranslation` làm fallback nếu cần.

**Kiểm chứng:** `MozhiTranslatorTest` case body lạ (HTML 200, JSON rỗng) → `PARSE`, không crash.

### CR-06 — Mozhi không kiểm tra đầu ra có tiếng Việt (low)

`MyMemoryTranslator.kt:70` có `looksVietnamese`, `MozhiTranslator.lookup` (`:41-64`) thì không. Mozhi proxy Google; khi upstream trả câu lỗi tiếng Anh hoặc giữ nguyên tiếng Anh, kết quả vẫn được coi là bản dịch OK và lưu cache/DB.

**Cách sửa:** thêm kiểm tra như MyMemory; không đạt → `NOT_VIETNAMESE` (đã có trong `JUNK_ANSWER`).

**Kiểm chứng:** test body trả nguyên câu tiếng Anh → `NOT_VIETNAMESE`.

### CR-09 — Phân loại lỗi nguồn chưa gom về một chỗ (medium, theo BE-28)

Planner/Backend đặt yêu cầu BE-28: gom phân loại vào **một** chỗ (`SourceFailure.kt`) để R36 (5xx bị dán nhãn quota) không tái phát.

**Hiện trạng (soát lại 21:02): đã gom một phần.** `SourceFailure.kt` đã có với đúng luật spec 1.16/1.17: `fromHttpStatus(status, hasQuota)`, `quota()`, `unavailable()`, `http()`; MyMemory (`:97-103`, `:115-125`) và Mozhi (`:125`) đã đi qua bảng chung; `SourceFailureTest` có 5 test (429 có/không quota, 5xx, 400/401/403, giữ httpStatus) và xanh.

**Còn lại (không chặn, sửa rẻ):**

- `HttpErrors.kt:67`: `isSourceError(status) = status == 429 || status in 500..599` — **không còn nơi nào gọi** (dead code) và nó chính là quy tắc sai cũ (gộp 429 với 5xx). Để lại thì người sau rất dễ dùng lại và tái sinh BUG-16 → **xoá**.
- `GeminiClient.kt:66-69`, `OpenAiCompatibleTranslator.kt:76-82` vẫn tự map `!isSuccessful → HTTP`, chưa đi qua bảng chung; 429 của Gemini thành `HTTP` (xem N-04). Nếu muốn "một chỗ" trọn vẹn: gọi `SourceFailure.fromHttpStatus(code, hasQuota = true)` ở 2 client có key.

**Kiểm chứng đã làm:** `grep -rn "in 500..599\|status == 429" app/src/main/java` → chỉ còn trong `SourceFailure.kt` và `HttpErrors.kt:67` (dead); `./gradlew :app:testDebugUnitTest` → 157 test, 0 fail.

### CR-10 — Tra WORD ra E19 "hết lượt" (high, QA phát hiện trên 1.0.4 nháp)

QA báo: trên 1.0.4, tra **từ** với hook quota ra `E19` (không phải E28/Mozhi). Truy ra nguyên nhân chính xác:

1. `MyMemoryTranslator.kt:43-49` kiểm tra `isQuotaBlockedToday()` **trước** `request.kind == TextKind.WORD`:

```kotlin
if (isQuotaBlockedToday()) return Failure(E4, QUOTA, 429)   // ← chạy trước
if (request.kind == TextKind.WORD) return Failure(E5, NOT_APPLICABLE)
```

Trong ngày đã tra hết quota một lần (cờ `keylessQuotaBlockedOn` được set), mọi lượt tra WORD đều trả `QUOTA` — dù MyMemory **không bao giờ nhận** WORD.

2. `ChainedTranslator`: Mozhi trả `NOT_APPLICABLE` (bị skip, không tính), Gemini/OpenAI trả `NO_KEY` (skip) → chain trả `QUOTA`.
3. `LookupPipeline.kt:161-163`: nhánh `QUOTA → E19` đứng **trước** `!hasNetwork` và trước mọi xử lý WORD → user thấy "Hết lượt dịch miễn phí hôm nay" khi tra một từ, thay vì "Chưa tải gói offline" (E3a) / kết quả ML Kit.

**Đây cũng là vi phạm AC37** ("E19 chỉ xét nguồn keyless"): WORD không đi nguồn keyless nào, nên không được phát E19.

**Cách sửa (1 dòng):** đưa `if (request.kind == TextKind.WORD) return NOT_APPLICABLE` lên trước `isQuotaBlockedToday()`. Nguyên tắc: nguồn không áp dụng cho loại text thì không bao giờ được báo quota/hết lượt.

**Kiểm chứng:** unit test mới `word_isNotApplicable_evenWhenQuotaBlocked` (flag quota = true + WORD → `NOT_APPLICABLE`), và test pipeline: WORD + cờ quota + chưa có gói offline → `E3a`, **không** `E19`; có gói → ML Kit. Chạy `./gradlew :app:testDebugUnitTest --tests '*MyMemoryTranslatorTest*' --tests '*LookupPipelineTest*'`.

## Đã tốt, đừng phá

- **Không log URL/text** ở cả 2 translator (`mymemory quota/5xx $status`, `mozhi io-<Class>`); có test `logsNeverContainTextOrUrl` (:145). Giữ nguyên khi thêm mã lỗi mới — không thêm câu query/body vào log.
- **Chặn câu lỗi tiếng Anh** của MyMemory bằng `looksVietnamese()` ở đầu ra (:70) — kể cả khi MyMemory trả 200 + text lỗi.
- **Chia byte UTF-8** đúng giới hạn 500B/request, có biên 450B (:201-202); `splitForQuery` ưu tiên cắt ở dấu câu.
- **Quota block theo ngày** (BE-20, `:43-46`) tránh gọi lại vô ích; `markQuotaExhausted` chỉ khi reason `QUOTA` (:58) — giữ đúng sau khi tách UNAVAILABLE, đừng đánh dấu hết lượt vì nguồn chết.
- **Instance-down cache 5 phút** của Mozhi (:39, :85) giải đúng vấn đề instance chết vẫn bị thử lại.
- **Tách lớp translator → `FailureReason` → pipeline map mã lỗi** là hướng đúng; chỉ cần mở rộng enum + map, không phải viết lại.
- **Timeout 4s/request MyMemory, 8s/instance Mozhi** hợp ngân sách E4 10s.
